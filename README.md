# Commerce Search & Ranking Engine

**Business question:** how can a shopper find the right product when their query is vague, incomplete, or uses
different words from the catalog?

A searchable storefront on Amazon's ESCI benchmark (1.8M products, 130K queries, English / Spanish / Japanese,
2.6M human relevance judgments) with keyword retrieval, an in-domain embedding retriever, hybrid search and a
learned reranker. Every approach is compared under the same evaluation conditions, broken down by query slice,
with latency and serving cost alongside quality.

> Results tables are generated by `csre eval` into `data/reports/eval_full_test.md`.

## What is in the repository

| Phase | What | Docs |
|---|---|---|
| 1. Data layer | ESCI + ESCI-S product pages (real departments, prices, ratings, images for 82% of products), attribute extraction, product graph, simulated traffic / feedback / replay, scale tiers to 25M products | [docs/data_layer.md](docs/data_layer.md) · [docs/phase1.md](docs/phase1.md) |
| 2. Retrieval & ranking | Multilingual BM25, two-tower subword encoder + HNSW, RRF / score fusion, LambdaMART rerankers (content-only and feedback-aware), E/S/C/I result-type classifier | [docs/architecture.md](docs/architecture.md) |
| 3. Evaluation | Rerank (judged sets) and full-catalog retrieval with unknown-relevance handling, slices, paired bootstrap CIs, latency, cost, robustness to query variants, systems benchmarks | [docs/architecture.md](docs/architecture.md#evaluation-protocol) |
| 4. Serving & demo | FastAPI service, storefront UI, model registry with versions, result cache, latency-budget fallbacks, feedback loop, explanations, shareable snapshot | `src/csre/serve/` |

## Quickstart

```bash
pip install -e ".[dev]"
make data        # phase 1: download ESCI + ESCI-S, build every dataset (~1 h on 4 vCPU / 16 GB)
make search      # phase 2: train encoder, build indexes, train rerankers, evaluate on the test split
make serve       # storefront + API on http://localhost:8000 (151K-product demo catalog)
make snapshot    # self-contained storefront page with precomputed results
make bench       # rerank-depth, ANN and catalog-scale benchmarks
pytest -q
```

## Ranking approaches

| Approach | `method` | Idea |
|---|---|---|
| Keyword | `bm25` | BM25 over title, brand, colour, bullets and description; Japanese via character bigrams |
| Semantic | `dense` | Two-tower encoder over words and character n-grams, trained on ESCI train queries with hard negatives |
| Hybrid (RRF) | `hybrid_rrf` | Reciprocal-rank fusion of the keyword and semantic lists |
| Hybrid (score fusion) | `hybrid` | Convex blend of z-normalised scores, weight tuned on dev |
| Reranker | `ltr` | LambdaMART on 57 content features (lexical, semantic, attribute match / conflict, negation, department fit, product, commerce) |
| Reranker + feedback | `ltr_fb` | Adds debiased click, cart, purchase and thumbs features from (simulated) shopper feedback |

## Honesty rules this project follows

* Relevance is known only inside each query's judged candidate set; unjudged results are reported as unknown.
* Offline relevance gains are not conversion impact. Feedback features come from a click simulator built on the
  same labels, so feedback-aware results are reported separately and labelled simulator-dependent.
* Prices and ratings are real ESCI-S values where available and simulated otherwise; every product says which.
